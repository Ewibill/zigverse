## 2026-08-07 · UNDULATION — the body swims itself (ZigCore.Structure v0.14.0 · Canon 37 laws)
**Chosen over `contact` on Glyph's instinct, Bill assenting:** cheaper, composes laws already present, and a swimming body would specify the contact problem better than arguing about it.
**Capability — `undulate()` + `slip()` (+ the `eel` bond archetype).** `age()` already tells every segment where it sits along the spine; feed that in as a PHASE OFFSET and the body carries a travelling wave head to tail. That is how every eel, fish, snake and worm moves — and it needed no new rhythm law, only `zigphase`'s clock read through `structure`'s geometry. `s = 1 - age` is distance behind the leading end; the wave lags with s and amplitude grows with s, because a fish's head barely moves and its tail sweeps wide. `slip()` gives the medium an ALONG and an ACROSS so a curve advances THROUGH itself the way a snake does rather than sweeping sideways.
**THE BUG THIS FOUND — the bend moment was not honest.** A bending moment is a THREE-body force; it was applied as an i/p pair. Linear momentum was conserved so `accel`'s existing momentum test passed — but that test used `chain`, which has bend 0, so the bend term had NEVER been checked. On a curved spine the pair left a free COUPLE: **net torque -208**. Under anisotropic drag that phantom spin rectified into phantom locomotion — a "swimmer" that travelled 22 body units with **waves = 0**, i.e. with no travelling wave at all, and whose direction ignored the wave entirely. **Fix:** g takes a force perpendicular to the g->p link with the lever arm about p that cancels b's moment (NOT merely antiparallel to b — on a curved body those differ, and the first attempt made torque worse at -400); p absorbs the remainder. Net force AND net torque now both zero to 1e-15. Guarded by structure_ref §12.
**TWO CLAIMS I HAD TO WITHDRAW, both corrected by measurement:**
1. **"Swimming requires drag anisotropy; isotropic is Purcell's scallop."** False here. This body has MASS, so it is a REACTIVE/inertial swimmer, not a viscous one — the wave sheds momentum. Measured: isotropic low drag swims FARTHER (3.15 BL) than anisotropic (0.60). Drag is a brake, not the engine. What IS required is non-reciprocity: travelling wave 0.60 vs standing oscillation -0.14, and reversing the wave reverses the animal. `slip` shapes CHARACTER, not existence. Recorded in the law's own comment and guarded so no one later mistakes slip for thrust.
2. **"A swimmer needs a compliant body."** Backwards. Stiff `spine` (bend 0.55) swims 2.23 BL/10s; compliant `eel` 0.45; limp `chain` 0.25. A reactive swimmer needs to TRANSMIT the wave along its length — a rope absorbs it locally. `eel` kept regardless: it is far more resolution-stable (0.45 -> 0.39 across 4x refinement where spine collapses 2.23 -> 0.48) and is a distinct character.
**Amplitude must scale with the bond** (`k * rest * gain`), not be a fixed number, or raising detail silently mutes the wave. Bench: 2.73 -> **37.6 units of travel in 3s against a 59-unit body**.

## 2026-08-07 · THE WGSL SPLICE — structure on the GPU (ZigWebGPU v0.37.0)
**`opts.structure`** — matter that is JOINED, spliced into the step kernel at the single `K_PREINT` hook like every other capability. Byte-identical when absent.

## 2026-08-09 · THE PARITY HARNESS EARNED ITSELF — a collapsing hash key
**`parity_contact.html` came back RED: worst relative 1.50e+0, worst absolute 3.69e+1 at agent 48.** Not a rounding difference — a genuine disagreement, the whole point of building the harness.
**And the harness was right about the wrong suspect.** Mirrored the GPU kernel exactly in JS and ran it against the CPU law on identical data: reproduced Bill's screen numbers to the digit (3.690e+1 at agent 48; agent 35 reading -8.36,-8.29,0.83 against 1.74,2.23,10.90). **So the GPU was never involved.** The bug was in `ZigCore.Contact.self` — Glyph's own CPU law, written the day before and passing its own test suite.
**THE BUG: the spatial-hash cell key was not INJECTIVE.** `key = a*73856093 ^ b*19349663` collapses whenever a term is zero, because `0 ^ x == x`. Cell (0,0)'s nine-cell neighbourhood yields only **SEVEN distinct keys**, so two buckets are walked TWICE and every pair inside them counted twice. Checked 6561 neighbourhoods: exactly one is broken — the origin. And a clump centred on the origin lands squarely in it. **Fix:** `key = a*4194304 + b`, a single multiply-add over a bounded lane, injective for any realistic world. Zero collisions across 4 million neighbourhoods tested.
**Result: worst difference 3.69e+1 → 2.56e-14.** CPU and kernel now agree to machine precision, and the clump still cannot push itself (net 1.5e-13).
**Why it hid:** the error is silent and POSITION-DEPENDENT. `contact_ref` passed throughout because its bodies were built along an axis or as coils offset from the origin — the one cell that breaks was never the busy one. A test suite can be green and a law still wrong in a place no test happens to stand.
**Guarded, both ways** (`contact_ref` §8): the key is asserted injective over every 3x3 neighbourhood across a wide range, AND a 96-agent clump placed deliberately ON THE ORIGIN is required to match brute force. The behavioural guard matters more than the structural one — it pins the exact case that was broken.
**Standing note:** every physics error found across these two days was caught by a numeric measurement, never by reading code — the bend moment's phantom torque, the force-based wave, the wake's unit mismatch, and now this. The parity harnesses exist because Glyph has no GPU; this one found a CPU bug instead, which is a better argument for them than the one they were built on.
